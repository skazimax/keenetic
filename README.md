# Выборочный AdGuard VPN на Keenetic

Комплект устанавливает AdGuard VPN CLI на Keenetic и направляет через него только устройства, назначенные выбранной политике. Отдельный WireGuard-интерфейс используется исключительно как переключатель в веб-интерфейсе и приложении Keenetic: его реальное состояние линка и наличие пиров не участвуют в маршрутизации.

Модель роутера, адрес SSH, имя интерфейса-переключателя и имя клиентской политики задаются при установке. Скрипты не содержат заранее выбранного номера WireGuard-интерфейса и не затрагивают другие туннели.

## Как это работает

- интерфейс-флаг выключен: AdGuard VPN отключён, его маршруты и правила удалены;
- интерфейс-флаг включён: запускается `adguardvpn-cli`, создаётся `tun0`, а клиенты выбранной политики получают правила маршрутизации через таблицу `100`;
- состав политики проверяется раз в 60 секунд, но правила обновляются только при изменении списка клиентов или после их потери;
- наличие `tun0` само по себе не считается признаком исправности: trigger проверяет реальную передачу трафика через туннель;
- если VPN отключился, завис или потерял авторизацию, клиентские правила удаляются и устройства временно используют обычный шлюз вместо потери интернета;
- IPv6 через `tun0` блокируется; решение рассчитано на IPv4;
- статус каждого запуска перезаписывает один небольшой файл и не раздувает лог;
- локальные сети `10.0.0.0/8` и `192.168.0.0/16` сохраняют обычные маршруты и не уходят в AdGuard VPN.

## 1. Подготовить Keenetic

В разделе обновления компонентов KeeneticOS установите:

- сервер SSH;
- поддержку OPKG;
- WireGuard VPN;
- поддержку файловой системы подключённого накопителя, если Entware будет на USB.

Для USB лучше использовать отдельный раздел EXT4. В веб-интерфейсе откройте настройки OPKG, выберите накопитель и запустите установку Entware. На моделях, поддерживающих Entware во внутренней памяти, можно выбрать внутреннее хранилище. После установки каталог `/opt` должен появляться автоматически после каждой перезагрузки.

Проверьте по SSH:

```sh
ROUTER_ADDRESS="router-address"
SSH_PORT="22"
ssh -p "$SSH_PORT" root@"$ROUTER_ADDRESS"
exec sh
/opt/bin/opkg update
```

Если `/opt/bin/opkg` отсутствует, дальнейшую установку пока не запускайте: сначала исправьте установку или автомонтирование Entware.

Официальная инструкция AdGuard требует не менее 22 МБ свободного постоянного места после установки зависимостей. На практике стоит оставить заметно больше для обновлений и диагностических логов.

## 2. Создать UI-флаг

В веб-интерфейсе Keenetic создайте отдельное WireGuard-подключение, которое не используется для передачи трафика. Можно использовать уже существующий неиспользуемый WireGuard-интерфейс, если у него нет пиров, маршрутов и реальной задачи.

- задайте любое понятное отображаемое имя;
- сгенерируйте приватный ключ;
- пиры и маршруты добавлять не нужно;
- оставьте переключатель выключенным до завершения установки и входа в AdGuard.

Скрипт смотрит только на сохранённое состояние `up/down` этого интерфейса. Наличие handshake, endpoint или адреса не проверяется. После создания найдите его внутреннее системное имя:

```sh
ndmc -c 'show running-config' | awk '$1 == "interface" && $2 ~ /^Wireguard/ { print $2 }'
```

Запомните соответствующий интерфейс и передайте его фактическое имя установщику через `--switch`. Проверить конкретный интерфейс можно командой `ndmc -c 'show interface ИМЯ'`. Не выбирайте интерфейс, который уже используется настоящим VPN-туннелем.

## 3. Создать клиентскую политику

В разделе приоритетов подключений создайте отдельную клиентскую политику. По умолчанию установщик ожидает имя `Policy0`, но его можно изменить через `--policy`. Оставьте в политике обычное подключение к интернету, чтобы устройства продолжали работать через стандартный шлюз, когда UI-флаг выключен.

Назначьте этой политике хотя бы одно зарегистрированное устройство. Членство в политике здесь используется как удобная метка клиента; более приоритетное Linux-правило перенаправляет его в `tun0` только при включённом флаге.

## 4. Развернуть комплект

Запустите на компьютере из этого каталога:

```sh
cd /media/max/2tb/VScode/keenetic

# Замените значения на параметры своего роутера.
ROUTER_ADDRESS="router-address"
SSH_PORT="22"
SWITCH_INTERFACE="REPLACE_WITH_INTERFACE_NAME"
POLICY_NAME="Policy0"

./deploy.sh \
    --host "$ROUTER_ADDRESS" \
    --port "$SSH_PORT" \
    --switch "$SWITCH_INTERFACE" \
    --policy "$POLICY_NAME"
```

Заранее задайте `ROUTER_ADDRESS`, `SSH_PORT`, `SWITCH_INTERFACE` и `POLICY_NAME` своими значениями. Параметры `--host` и `--switch` обязательны. Пароль SSH будет запрошен один раз и нигде не сохраняется.

Установщик:

- обновит Entware и поставит `curl`, `ca-certificates`, `iptables`, `sudo`;
- установит актуальный официальный release AdGuard VPN CLI для архитектуры роутера;
- создаст постоянный профиль `/opt/home/adguardvpn`;
- установит trigger, автозапуск и self-test;
- отключит конфликтующие хуки из официального примера, если они были установлены раньше;
- сохранит заменённые файлы в `/opt/backup/adguard-vpn-trigger/<дата>`.

Повторный запуск допустим. Текущий профиль и авторизация AdGuard не удаляются.

## 5. Войти в AdGuard VPN

UI-флаг должен оставаться выключенным. Первый вход и первое подключение обязательно выполняйте в обычной интерактивной SSH-сессии: AdGuard VPN CLI показывает ссылку авторизации и задаёт вопрос о режиме маршрутизации. Перед этим остановите polling-сервис, чтобы он не запускал CLI параллельно.

```sh
exec sh
/opt/etc/init.d/S99adguard-vpn-trigger stop
export HOME=/opt/home/adguardvpn
export SSL_CERT_FILE=/opt/etc/ssl/certs/ca-certificates.crt
export PATH=/opt/bin:/opt/sbin:/usr/bin:/bin:/usr/sbin:/sbin
adguardvpn-cli login
```

Откройте предложенную ссылку, войдите в аккаунт и обязательно дождитесь сообщения `Successfully Logged in`. Не закрывайте SSH-сессию сразу после подтверждения в браузере: CLI проверяет результат с интервалом около 20 секунд.

Посмотрите доступные локации и выполните первое подключение к выбранной стране или городу:

```sh
adguardvpn-cli list-locations
adguardvpn-cli connect -l ISO_КОД
```

На MIPS/MIPSel при очень долгом первом подключении сначала остановите команду `Ctrl+C`, отключите post-quantum и повторите её:

```sh
adguardvpn-cli config set-post-quantum off
adguardvpn-cli connect -l ISO_КОД
```

На вопрос `Would you like to set default routes in TUN mode?` ответьте `yes`. Режим `auto` нужен самому CLI для корректного создания `tun0`. Во время этой короткой ручной проверки default route AdGuard остаётся активным до команды `disconnect`. При дальнейших подключениях trigger сразу удаляет его из основной таблицы и создаёт отдельную таблицу только для выбранных клиентов.

Проверьте интерфейс, отключите тестовое соединение и верните сервис:

```sh
ip link show tun0
adguardvpn-cli disconnect
adguardvpn-cli config set-protocol auto
adguardvpn-cli config set-debug-logging off
/opt/etc/init.d/S99adguard-vpn-trigger start
```

На более производительных ARM/AArch64-моделях сначала оставьте post-quantum в значении по умолчанию. После ручной инициализации trigger использует неинтерактивное подключение.

## 6. Проверить работу

Сначала запустите диагностику с выключенным UI-флагом:

```sh
/opt/bin/adguard-vpn-selftest
```

Затем включите выбранный интерфейс-флаг в приложении Keenetic и либо подождите до 60 секунд, либо запустите проверку сразу:

```sh
/opt/scripts/adguard-vpn-trigger.sh
/opt/bin/adguard-vpn-selftest
```

На устройстве из `Policy0` проверьте внешний IP. На устройстве вне политики внешний IP должен остаться провайдерским. После выключения флага повторите проверку: `tun0` и клиентские правила должны исчезнуть.

При включённом флаге исправный self-test должен показать:

- `UI switch is ON`;
- ненулевое число клиентов политики и разрешённых IPv4-адресов;
- `tun0 is up`;
- default route через `tun0` в VPN-таблице;
- клиентские правила с заданным приоритетом;
- подключённую цепочку `ADGUARD_FORWARD`;
- итог `0 error(s), 0 warning(s)`.

Предупреждение о пустой политике нормально только до назначения клиентов. Предупреждение о неавторизованном профиле означает, что `login` выполнялся с другим значением `HOME` или не был завершён.

Если UI-флаг включён, но AdGuard VPN разорвал сессию, следующий цикл polling удалит старые правила, завершит зависший tunnel-daemon, удалит занятый им управляющий socket и подключится заново. После команды `connect` trigger ждёт успешной передачи тестового пакета через `tun0`. Если переподключение не удалось или профиль действительно вышел из аккаунта, trigger оставит клиентов на обычном шлюзе и запишет причину в status log. При штатной остановке Entware VPN-процессы и правила удаляются до остановки сети. Повторная авторизация аккаунта всё равно выполняется вручную через `adguardvpn-cli login`.

Полезные команды:

```sh
/opt/etc/init.d/S99adguard-vpn-trigger status
cat /opt/var/log/adguard-vpn-trigger.status
cat /opt/var/run/adguardvpn.clients
ip rule show
ip route show table 100
/opt/sbin/iptables -t nat -S POSTROUTING
```

IP-адреса клиентов берутся сначала из DHCP bindings, затем из таблицы соседей. Чтобы правило не переехало на другое устройство, зарегистрируйте клиент в Keenetic и закрепите за ним постоянный DHCP-адрес.

## 7. Проверить перезагрузку

Перед перезагрузкой выключите UI-флаг, затем перезагрузите роутер. После появления интернета выполните:

```sh
/opt/bin/adguard-vpn-selftest
```

При запуске self-test из Telnet вложенный `ndmc` может быть недоступен из-за ограничения Keenetic CLI. В этом случае self-test использует последний снимок `running-config`, успешно прочитанный trigger, и выводит предупреждение вместо ложной ошибки.

Убедитесь, что Entware смонтирован и фоновый процесс работает. После этого включите UI-флаг и проверьте ещё раз через 60–90 секунд. Задержка нужна, потому что после старта Keenetic сначала поднимает накопитель, WAN, DNS и только затем AdGuard VPN.

Если сразу после перезагрузки VPN ещё не появился, подождите один дополнительный цикл. Не запускайте несколько копий trigger вручную: встроенная lock-директория не даст им повредить правила, но лишние запуски затруднят диагностику.

## Если AdGuard VPN не подключается

Если авторизация и `list-locations` работают, но `connect` долго не создаёт `tun0`:

1. Остановите polling-сервис и повторите подключение в интерактивной SSH-сессии.
2. Убедитесь, что используется постоянный `HOME=/opt/home/adguardvpn` и правильный `SSL_CERT_FILE`.
3. Ответьте `yes` на первый вопрос о default routes.
4. На MIPS/MIPSel временно отключите post-quantum и повторите подключение.
5. Если автоматический протокол не работает, отдельно проверьте `http2` и `quic`.

Команды диагностики:

```sh
/opt/etc/init.d/S99adguard-vpn-trigger stop
export HOME=/opt/home/adguardvpn
export SSL_CERT_FILE=/opt/etc/ssl/certs/ca-certificates.crt

adguardvpn-cli config set-debug-logging on
adguardvpn-cli config set-protocol http2
adguardvpn-cli connect -l ISO_КОД

tail -100 /opt/home/adguardvpn/.local/share/adguardvpn-cli/app.log
```

Для проверки QUIC замените `http2` на `quic`. После диагностики верните автоматический выбор, выключите debug logging и запустите сервис:

```sh
adguardvpn-cli disconnect
adguardvpn-cli config set-protocol auto
adguardvpn-cli config set-debug-logging off
/opt/etc/init.d/S99adguard-vpn-trigger start
```

Не оставляйте debug logging включённым постоянно: `app.log` будет расти и расходовать место Entware.

## Настройки

Основной файл настроек:

```text
/opt/etc/adguard-vpn-trigger.conf
```

Пример:

```sh
SWITCH_IF="SYSTEM_INTERFACE_NAME"
POLICY_NAME="Policy0"
TABLE_ID="100"
RULE_PRIORITY="90"
ADGUARD_HOME="/opt/home/adguardvpn"
INTERVAL="60"
```

После изменения выполните:

```sh
/opt/etc/init.d/S99adguard-vpn-trigger restart
```

Не уменьшайте `INTERVAL` ниже 15 секунд. Для обычного управления через приложение 60 секунд достаточно и создаёт существенно меньше обращений к конфигурации Keenetic.

Рабочая конфигурация AdGuard VPN CLI для этой схемы обычно выглядит так:

```text
Tunnel routing mode: auto
Protocol: auto
Debug logging: off
```

Значение post-quantum выбирается по производительности конкретного роутера.

## Контроль памяти и логов

После установки и после первой перезагрузки сохраните исходные значения памяти. Self-test уже выводит `free` и процессы `ndm`, AdGuard VPN и polling-сервиса:

```sh
/opt/bin/adguard-vpn-selftest
```

Для наблюдения в течение нескольких дней периодически сравнивайте:

```sh
free
ps w | awk 'NR == 1 || /[n]dm|[a]dguardvpn|[S]99adguard/'
du -h /opt/var/log/adguard-vpn-trigger.status
du -h /opt/home/adguardvpn/.local/share/adguardvpn-cli/app.log
```

`adguard-vpn-trigger.status` перезаписывается на каждом цикле и не должен расти. Основной `app.log` принадлежит AdGuard VPN CLI; особенно быстро он растёт при включённом debug logging. Если память `ndm` стабильно увеличивается, сначала увеличьте `INTERVAL`, например до 120–300 секунд, перезапустите сервис и сравните темп роста. Это уменьшит число обращений `ndmc` к конфигурации Keenetic.

Не оценивайте утечку только по полю `used`: Linux использует свободную RAM под cache. Сравнивайте также `available`, RSS/VSZ процесса `ndm`, размер логов и поведение после нескольких одинаковых циклов включения и выключения UI-флага.

## Откат

Сначала выключите UI-флаг, чтобы trigger штатно удалил правила, затем остановите сервис:

```sh
/opt/scripts/adguard-vpn-trigger.sh
/opt/etc/init.d/S99adguard-vpn-trigger stop
```

Резервные копии находятся в `/opt/backup/adguard-vpn-trigger/`. Чтобы вернуть конкретную версию, скопируйте из нужного каталога файлы обратно в их исходные места и перезапустите сервис. Сам AdGuard VPN CLI и его профиль установщик при откате автоматически не удаляет.

## Файлы комплекта

- `deploy.sh` — доставка и запуск установки с компьютера;
- `install.sh` — установщик, выполняемый на роутере;
- `adguard-vpn-trigger.sh` — синхронизация UI-флага, клиентской политики и маршрутов;
- `S99adguard-vpn-trigger` — ограниченный по размеру фоновый опрос и автозапуск;
- `adguard-vpn-selftest.sh` — проверка окружения, маршрутов, процесса и памяти;
- `adguard-vpn-trigger.conf.example` — пример конфигурации.
